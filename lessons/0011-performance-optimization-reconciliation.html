Lesson 0011: Performance Optimization & Reconciliation

Translating Zone.js change detection & OnPush strategy to Virtual DOM Fiber reconciliation, React.memo, useMemo, useCallback, and the React 19 Compiler

1. Performance & Change Detection Translation Matrix

In Angular, Zone.js monkey-patches asynchronous browser APIs to trigger global dirty checking across the component tree, optimized via ChangeDetectionStrategy.OnPush and Signals. React relies on Virtual DOM Fiber reconciliation: when setState is called, React renders the component and its children, diffs the new tree against the old tree, and commits only the minimal DOM changes to the browser.

2. Deep Dive: Referential Equality & The Re-render Cascade

Angular developers moving to React must grasp how JavaScript referential equality (===) governs React's rendering lifecycle:

Why Unmemoized Functions & Objects Trigger Re-renders:

In React, whenever a parent component renders, any object literal ({ id: 1 }) or inline arrow function (() => doSomething()) declared inside the function body is allocated as a completely new memory reference. If passed to a child wrapped in React.memo(), the shallow comparison fails (oldProps.onClick !== newProps.onClick), forcing the child to re-render anyway!

The Solution: `useCallback` and `useMemo` 
// ParentComponent.tsx
import React, { useState, useCallback, useMemo } from 'react';

export function ParentComponent() {
  const [query, setQuery] = useState('');
  const [items, setItems] = useState<Item[]>([]);

  // 1. Cache function reference across renders
  const handleDelete = useCallback((id: string) => {
    setItems(prev => prev.filter(item => item.id !== id));
  }, []); // Stable reference across all renders

  // 2. Cache expensive calculation across renders
  const filteredItems = useMemo(() => {
    return items.filter(item => item.name.toLowerCase().includes(query.toLowerCase()));
  }, [items, query]); // Only recomputes when items or query change

  return <MemoizedList items={filteredItems} onDelete={handleDelete} />;
}

3. Side-by-Side Code Comparison: Real-Time High-Throughput Financial Data Grid

Compare a real-time table rendering hundreds of streaming updates per second in Angular (OnPush + Pure Pipe) vs. React (React.memo + useCallback + useMemo):

Angular Component (OnPush + Pure Pipe)

// stock-row.component.ts
import { Component, Input, ChangeDetectionStrategy } from '@angular/core';

@Component({
  selector: 'app-stock-row',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <tr>
      <td>{{ stock.symbol }}</td>
      <td [class.up]="stock.price > stock.prevPrice">
        {{ stock.price | currency }}
      </td>
      <td>
        <button (click)="onSelect.emit(stock.symbol)">Details</button>
      </td>
    </tr>
  `
})
export class StockRowComponent {
  @Input() stock!: Stock;
  @Output() onSelect = new EventEmitter<string>();
}

React Component (React.memo + useCallback)

// StockRow.tsx
import React from 'react';

interface StockRowProps {
  stock: Stock;
  onSelect: (symbol: string) => void;
}

// React.memo skips re-rendering if stock and onSelect references do not change
export const StockRow = React.memo(function StockRow({ stock, onSelect }: StockRowProps) {
  const isUp = stock.price > stock.prevPrice;

  return (
    <tr>
      <td>{stock.symbol}</td>
      <td className={isUp ? 'text-green-600' : 'text-red-600'}>
        ${stock.price.toFixed(2)}
      </td>
      <td>
        <button onClick={() => onSelect(stock.symbol)}>Details</button>
      </td>
    </tr>
  );
});

4. Critical Performance Gotchas for Angular Leads

  1. Premature Optimization Overhead:
    Wrapping simple mathematical calculations or string interpolations (e.g. useMemo(() => a + b, [a, b])) actually degrades performance due to dependency array comparison and memory overhead. Use useMemo only for operations that genuinely cost significant CPU time (e.g. sorting/filtering thousands of array items, parsing large JSON objects, or calculating geometry).
  2. Virtual DOM Re-rendering != Real DOM Painting:
    A React component re-rendering simply means calling its function to produce a new virtual element tree. If the resulting virtual tree matches the previous tree, zero real DOM writes occur. Do not panic over re-renders unless they cause measurable frame drops or slow interactions.
  3. The React 19 Compiler Shift:
    In React 19, the new React Compiler analyzes pure JavaScript semantics at build time and automatically memoizes values and functions, eliminating the need to manually sprinkle useMemo, useCallback, and React.memo across standard codebase files.
