Lesson 0020: Microfrontends & Module Federation

Translating Angular Module Federation (@angular-architects/module-federation) to Modern React Module Federation 2.0 and Dynamic Remotes

1. Microfrontend Architecture Translation Matrix

Enterprise Angular architectures frequently deploy microfrontends using Manfred Steyer's @angular-architects/module-federation to dynamically mount remote Angular feature modules or Web Components. In the React ecosystem, microfrontends are powered by Module Federation 2.0 (@module-federation/enhanced, Rsbuild, and Webpack), enabling independently deployed remote React applications to share dependencies (like react, react-dom, and @tanstack/react-query) as runtime singletons without duplicate downloads.

Concept Angular Microfrontends React Microfrontends (Module Federation 2.0)
Federation Plugin @angular-architects/module-federation with withModuleFederationPlugin() @module-federation/enhanced or @originjs/vite-plugin-federation
Host / Shell App Configuration Declaring remotes in federation.config.js new ModuleFederationPlugin({ name: 'host', remotes: { checkout: 'checkout@https://...' } })
Shared Singleton Runtime shareAll({ singleton: true, strictVersion: true }) shared: { react: { singleton: true, requiredVersion: '^19.0.0' }, 'react-dom': { singleton: true } }
Dynamic Remote Loading loadRemoteModule({ type: 'module', remoteEntry: '...', exposedModule: './Module' }) React.lazy(() => import('checkout/Cart')) or runtime loadRemote('checkout/Cart')
Remote Fault Isolation Angular ErrorHandler / Router error catches React Error Boundaries (<ErrorBoundary fallback={<RemoteFallback />}>) wrapping dynamic remotes

2. Architecture: Shared Singleton Runtimes and Error Boundaries

The most critical requirement in React microfrontends is ensuring that only one instance of react and react-dom executes in the browser memory. Multiple React instances break hook state dispatchers. Module Federation solves this via the singleton: true configuration:

Critical React Rule for Microfrontends:

Always configure react and react-dom as singleton: true and strictVersion: true in both Host and Remote configurations. If versions drift across minor breaking changes, federation runtime negotiates or logs a clear version mismatch warning.

3. Side-by-Side Code Comparison: Consuming a Remote Feature in the Host App

Angular Route Loading Remote Module

// app.routes.ts (Angular Host)
import { Routes } from '@angular/router';
import { loadRemoteModule } from '@angular-architects/module-federation';

export const routes: Routes = [
  {
    path: 'checkout',
    loadChildren: () =>
      loadRemoteModule({
        type: 'module',
        remoteEntry: 'https://checkout.domain.com/remoteEntry.js',
        exposedModule: './CheckoutModule'
      }).then(m => m.CheckoutModule)
  }
];

React Host App with Lazy Remote & Error Boundary

// HostApp.tsx (React Host)
import React, { Suspense } from 'react';
import { ErrorBoundary } from './ErrorBoundary';

// Dynamically imported remote exposed component
const RemoteCheckout = React.lazy(() => import('checkoutApp/CheckoutFlow'));

export function App() {
  return (
    <div className="host-container">
      <nav>Host Navigation Bar</nav>
      
      <main>
        <ErrorBoundary fallback={<p>Checkout service temporarily unavailable.</p>}>
          <Suspense fallback={<div>Loading Checkout...</div>}>
            <RemoteCheckout userToken="token-123" />
          </Suspense>
        </ErrorBoundary>
      </main>
    </div>
  );
}

4. Key Architectural Takeaways for Angular Leads

  • Zero Glue Code for Props: Unlike Angular where remotes often require custom event bridges or Web Component wrapping to communicate with the host, React remotes receive standard React props, callbacks, and context seamlessly across boundaries.
  • Resilient Microfrontends via Error Boundaries: If a remote server experiences an outage or throws a runtime error, React's <ErrorBoundary> isolates the crash to that specific widget without bringing down the host shell application.
