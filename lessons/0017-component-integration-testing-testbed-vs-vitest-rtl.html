Lesson 0017: Component & Integration Testing

Translating Angular TestBed, ComponentFixture, By.css, and fakeAsync to Vitest, React Testing Library, user-event, and accessibility queries

1. Testing Architecture Translation Matrix

In Angular, component tests rely on TestBed, ComponentFixture, and DOM querying via CSS selectors (By.css('.btn')). In modern React Web development, testing has standardized around vitest and @testing-library/react (RTL), emphasizing user-centric accessibility queries (testing components the way real users and screen readers interact with them).

📦 Essential Testing Stack for Modern React

The standard modern testing toolchain in React:

npm install -D vitest @testing-library/react @testing-library/user-event @testing-library/jest-dom jsdom
  • vitest: Blazing-fast test runner native to modern bundlers.
  • @testing-library/react: Simple and complete React DOM testing utilities.
  • @testing-library/user-event: Advanced user action simulator.
  • @testing-library/jest-dom: Custom DOM matchers (toBeInTheDocument, toBeDisabled, toHaveValue).
  • jsdom: Pure JavaScript implementation of the DOM for Node test environments.

2. Architecture: Testing User Behavior Instead of Implementation Details

Angular unit tests frequently assert on internal class properties (e.g. expect(component.isSubmitting).toBe(true)) or query internal CSS class names (By.css('.btn-primary')). React Testing Library enforces the golden rule of testing:

The Testing Library Philosophy:

"The more your tests resemble the way your software is used, the more confidence they can give you."

  • Query by Accessible Role: screen.getByRole('button', { name: /login/i }) ensures your UI is accessible to screen readers and resilient to CSS/DOM refactoring.
  • Query by Label: screen.getByLabelText(/username/i) ensures inputs are properly associated with <label> elements.
  • Never assert on private state: Test what appears on the screen (the output), not the internal useState variables.

3. Side-by-Side Code Comparison: User Signup Form Integration Test

Compare how a user signup form with validation and asynchronous submission is tested in Angular (TestBed) vs. React (Vitest + React Testing Library):

Angular TestBed Test

// signup.component.spec.ts
import { ComponentFixture, TestBed, fakeAsync, tick } from '@angular/core/testing';
import { SignupComponent } from './signup.component';
import { By } from '@angular/platform-browser';
import { of } from 'rxjs';

describe('SignupComponent', () => {
  let component: SignupComponent;
  let fixture: ComponentFixture<SignupComponent>;

  beforeEach(async () => {
    await TestBed.configureTestingModule({
      declarations: [SignupComponent],
    }).compileComponents();

    fixture = TestBed.createComponent(SignupComponent);
    component = fixture.componentInstance;
    fixture.detectChanges();
  });

  it('submits form with valid data', fakeAsync(() => {
    // Fill inputs via nativeElement
    const emailInput = fixture.debugElement.query(By.css('input[type="email"]')).nativeElement;
    emailInput.value = 'lead@company.com';
    emailInput.dispatchEvent(new Event('input'));
    fixture.detectChanges();

    // Click submit button
    const submitBtn = fixture.debugElement.query(By.css('button[type="submit"]')).nativeElement;
    submitBtn.click();
    fixture.detectChanges();
    tick();

    // Verify component internal state
    expect(component.isSubmitted).toBe(true);
  }));
});

React Vitest + React Testing Library Test

// SignupForm.test.tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, it, expect, vi } from 'vitest';
import { SignupForm } from './SignupForm';

describe('SignupForm', () => {
  it('submits form with valid data', async () => {
    const user = userEvent.setup();
    const handleSubmit = vi.fn();

    render(<SignupForm onSubmit={handleSubmit} />);

    // 1. Fill inputs using accessible labels
    const emailInput = screen.getByLabelText(/email address/i);
    await user.type(emailInput, 'lead@company.com');

    // 2. Click submit button using accessible role
    const submitBtn = screen.getByRole('button', { name: /sign up/i });
    await user.click(submitBtn);

    // 3. Assert on what the user sees & callback execution
    expect(handleSubmit).toHaveBeenCalledWith({ email: 'lead@company.com' });
    expect(screen.getByText(/welcome aboard/i)).toBeInTheDocument();
  });
});

4. Critical Testing Gotchas for Angular Leads

  1. Always await userEvent Interactions:
    Unlike fireEvent.click() (which only triggers a single synthetic click), userEvent.click() simulates true browser sequences (hover → mousedown → focus → mouseup → click). Because userEvent actions are asynchronous, you must always await user.click(...) and await user.type(...).
  2. Avoid container.querySelector('.my-class'):
    Querying with CSS selectors breaks whenever classes or DOM structures are refactored. Always prioritize screen.getByRole, screen.getByLabelText, and screen.getByText.
