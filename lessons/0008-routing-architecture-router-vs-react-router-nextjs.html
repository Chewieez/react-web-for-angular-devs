2. Architecture: Layout Routes & State Persistence

In Angular, nested views are rendered using <router-outlet>. React Router uses the exact same pattern with <Outlet />:

How Layout Routes Prevent Redundant Re-Renders:

When a user navigates between /admin/users and /admin/analytics, only the child route component switches inside <Outlet />. The parent <AdminLayout> (with its sidebar, topbar, and search inputs) stays mounted—preserving scroll position and UI state without flashing!

// AppRoutes.tsx
import { createBrowserRouter, RouterProvider, Outlet } from 'react-router';

function AdminLayout() {
  return (
    <div className="admin-shell">
      <Sidebar />
      <main className="admin-content">
        <Outlet /> {/* Child route renders here (like ) */}
      </main>
    </div>
  );
}

const router = createBrowserRouter([
  {
    path: '/admin',
    element: <AdminLayout />,
    children: [
      { path: 'users', element: <UserManagement /> },
      { path: 'analytics', element: <AnalyticsDashboard /> }
    ]
  }
]);

3. Implementing Route Guards & Protected Layouts

Angular developers often wonder where CanActivate guards go in React. In React Router, you protect routes by wrapping them in a Protected Layout Component:

Angular CanActivate Guard

// auth.guard.ts
@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {
  constructor(private auth: AuthService, private router: Router) {}

  canActivate(): boolean | UrlTree {
    if (this.auth.isLoggedIn) {
      return true;
    }
    return this.router.createUrlTree(['/login']);
  }
}

// app-routing.module.ts
const routes: Routes = [
  {
    path: 'dashboard',
    component: DashboardComponent,
    canActivate: [AuthGuard]
  }
];

React Protected Route Wrapper

// ProtectedRoute.tsx
import React from 'react';
import { Navigate, Outlet, useLocation } from 'react-router';
import { useAuth } from './AuthContext';

export function ProtectedRoute() {
  const { isAuthenticated, isLoading } = useAuth();
  const location = useLocation();

  if (isLoading) {
    return <div className="loader">Checking authentication...</div>;
  }

  if (!isAuthenticated) {
    // Redirect to login while preserving previous attempted URL
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  return <Outlet />; // Renders protected child routes
}

// Router Setup:
const router = createBrowserRouter([
  {
    element: <ProtectedRoute />, // Auth Guard
    children: [
      { path: '/dashboard', element: <Dashboard /> },
      { path: '/settings', element: <Settings /> }
    ]
  },
  { path: '/login', element: <Login /> }
]);

4. Side-by-Side Code Comparison: Dynamic Route with Parameter Inspection

Compare how dynamic URL parameters (e.g. /users/:userId) and programmatic navigation are accessed in Angular vs React:

Angular Component (ActivatedRoute)

// user-detail.component.ts
import { Component, OnInit, OnDestroy } from '@angular/core';
import { ActivatedRoute, Router } from '@angular/router';
import { Subscription } from 'rxjs';

@Component({
  selector: 'app-user-detail',
  templateUrl: './user-detail.component.html'
})
export class UserDetailComponent implements OnInit, OnDestroy {
  userId!: string;
  private sub!: Subscription;

  constructor(
    private route: ActivatedRoute,
    private router: Router
  ) {}

  ngOnInit(): void {
    // Subscribe to param changes
    this.sub = this.route.params.subscribe(params => {
      this.userId = params['userId'];
      this.loadUser(this.userId);
    });
  }

  goBack(): void {
    this.router.navigate(['/users']);
  }

  ngOnDestroy(): void {
    this.sub?.unsubscribe();
  }
}

React Component (useParams & useNavigate)

// UserDetail.tsx
import React, { useEffect } from 'react';
import { useParams, useNavigate } from 'react-router';

export function UserDetail() {
  // 1. Read dynamic param directly (no subscription needed!)
  const { userId } = useParams<{ userId: string }>();
  const navigate = useNavigate();

  useEffect(() => {
    if (userId) {
      loadUser(userId);
    }
  }, [userId]); // Automatically re-runs when URL param changes

  function handleGoBack() {
    navigate('/users');
  }

  return (
    <div className="user-detail-card">
      <h2>User Profile: {userId}</h2>
      <button onClick={handleGoBack}>← Back to Users</button>
    </div>
  );
}

5. Critical Routing Gotchas for Angular Leads

  1. Never Use Plain <a href="..."> for Internal Navigation:
    Using <a href="/dashboard"> performs a hard browser reload, dumping all React state and re-fetching the entire bundle. Always use <Link to="/dashboard"> or <NavLink> for client-side transitions.
  2. useParams() Returns Strings:
    All path parameters extracted with useParams() are strings. If your route is /products/:id and you expect a number, explicitly convert it: const id = Number(params.id).
  3. Active Link Styling: routerLinkActive vs NavLink:
    In Angular, you attach routerLinkActive="active". In React Router, use the <NavLink> component with a callback function: 
    <NavLink
  to="/dashboard"
  className={({ isActive }) => (isActive ? 'nav-link active' : 'nav-link')}
>
  Dashboard
</NavLink>
  4. Programmatic Redirects in Render:
    Never call navigate('/login') directly inside the body of your component function during render. Instead, return <Navigate to="/login" replace /> as a JSX element or invoke navigate() inside an event handler / useEffect.
