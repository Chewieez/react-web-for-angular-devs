Lesson 0009: HTTP Data Pipelines & Server State

Translating Angular HttpClient, RxJS Observables, async pipes, and switchMap pipelines to TanStack React Query v5

1. HTTP & Server State Translation Matrix

In Angular, HTTP requests are managed through HttpClient returning RxJS Observable streams, consumed via template async pipes or manual subscriptions. In modern React, the industry standard is @tanstack/react-query (v5): an asynchronous server-state library that handles caching, background synchronization, automatic deduplication, and declarative mutations.

2. Architecture: Server State vs. Client State

Angular developers often treat all data identically by storing server responses inside NgRx stores or service BehaviorSubjects. In React, architectural best practice strictly separates state into two categories:

1. Server State (Handled by TanStack Query):

Server state is data owned by a remote server (e.g. database records, user profiles, invoices). It is asynchronous, shared across multiple clients, and can become stale at any time. TanStack Query automatically manages caching, background re-fetching, deduplication, and stale status without requiring global Redux/NgRx actions!

2. Client State (Handled by useState / Zustand):

Client state is purely synchronous, local UI data (e.g. is a sidebar expanded, which modal is open, text typed in an unsaved form input). This belongs in useState or lightweight stores like zustand.

3. Query Keys as Reactive Dependency Arrays

In Angular, when user filters change, you pipe a BehaviorSubject through switchMap to cancel previous HTTP requests and fetch new data. In TanStack Query, the queryKey array provides this exact behavior declaratively:

Declarative Auto-Refetching with Query Keys:

Whenever any variable inside the queryKey array changes (e.g. role or page), TanStack Query automatically cancels any inflight request and fetches fresh data for the new key:

// TanStack Query v5 Syntax:
export function UserList() {
  const [role, setRole] = useState('admin');
  const [page, setPage] = useState(1);

  // When `role` or `page` changes, useQuery automatically re-fetches!
  const { data, isPending } = useQuery({
    queryKey: ['users', { role, page }],
    queryFn: () => fetchUsers({ role, page }),
    staleTime: 1000 * 60 * 5, // Data is fresh for 5 minutes
  });

  return ( ... );
}

4. Side-by-Side Code Comparison: Full CRUD User Management Table

Compare an enterprise user table featuring role filtering, loading spinners, and an asynchronous delete mutation in Angular vs. React:

Angular Component (HttpClient + RxJS switchMap)

// user-list.component.ts
import { Component, OnInit } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { BehaviorSubject, switchMap, catchError, of } from 'rxjs';

interface User { id: string; name: string; role: string; }

@Component({
  selector: 'app-user-list',
  templateUrl: './user-list.component.html'
})
export class UserListComponent implements OnInit {
  selectedRole$ = new BehaviorSubject<string>('all');
  users$ = this.selectedRole$.pipe(
    switchMap(role =>
      this.http.get<User[]>(`/api/users?role=${role}`).pipe(
        catchError(() => of([]))
      )
    )
  );

  constructor(private http: HttpClient) {}

  onRoleChange(role: string): void {
    this.selectedRole$.next(role);
  }

  deleteUser(id: string): void {
    this.http.delete(`/api/users/${id}`).subscribe(() => {
      // Manually trigger refetch by re-emitting role
      this.selectedRole$.next(this.selectedRole$.getValue());
    });
  }
}

React Component (TanStack Query useQuery & useMutation)

// UserList.tsx
import React, { useState } from 'react';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import axios from 'axios';

interface User { id: string; name: string; role: string; }

export function UserList() {
  const [selectedRole, setSelectedRole] = useState<string>('all');
  const queryClient = useQueryClient();

  // 1. Declarative Query (replaces RxJS switchMap & HttpClient)
  const { data: users = [], isPending, isError } = useQuery<User[]>({
    queryKey: ['users', selectedRole],
    queryFn: async () => {
      const res = await axios.get(`/api/users?role=${selectedRole}`);
      return res.data;
    }
  });

  // 2. Mutation with automatic cache invalidation
  const deleteMutation = useMutation({
    mutationFn: (id: string) => axios.delete(`/api/users/${id}`),
    onSuccess: () => {
      // Invalidate & automatically trigger refetch
      queryClient.invalidateQueries({ queryKey: ['users'] });
    }
  });

  if (isPending) return <div className="loader">Loading users...</div>;
  if (isError) return <div className="error">Error loading users</div>;

  return (
    <div className="user-table-card">
      <select value={selectedRole} onChange={(e) => setSelectedRole(e.target.value)}>
        <option value="all">All Roles</option>
        <option value="admin">Admin</option>
        <option value="member">Member</option>
      </select>

      <ul>
        {users.map(user => (
          <li key={user.id}>
            {user.name} ({user.role})
            <button
              onClick={() => deleteMutation.mutate(user.id)}
              disabled={deleteMutation.isPending}
            >
              Delete
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}

5. Critical Data Pipeline Gotchas for Angular Leads

  1. The useEffect Fetching Anti-Pattern:
    Never write raw data fetching in useEffect(() => { fetch(...) }, []). It lacks caching, produces race conditions during fast typing, double-fetches in Strict Mode, and requires dozens of lines of manual loading/error state management. Always use useQuery.
  2. staleTime vs. gcTime in TanStack Query v5:
    • staleTime (default: 0): How long data is considered fresh. When data is stale, it will be refetched in the background upon window focus or component mount.
    • gcTime (default: 5 minutes, previously cacheTime): How long inactive query data remains cached in memory before being garbage collected.
  3. Query Keys Must Be Serializable Objects/Arrays:
    TanStack Query hashes query keys deterministically. Pass primitives, arrays, and objects (e.g. ['todos', { status, page }]). Never pass non-serializable objects or functions into queryKey.
