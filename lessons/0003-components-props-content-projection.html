Lesson 0003: Components, Props & Content Projection

Translating @Input, @Output EventEmitter, <ng-content>, and <ng-template> to Props, Callbacks, children, Named Slots, and Render Props

1. Inputs & Outputs vs. Props & Callbacks

In Angular, components are stateful classes decorated with @Component(). Data flows in via @Input() decorators (or Angular 17+ input() signals) and out via @Output() EventEmitter instances (or output()). In React, components are pure or semi-pure JavaScript functions, and both inputs and event listeners are passed in a single unified props argument.

2. Content Projection: 4 Core Patterns in React

Angular developers rely heavily on <ng-content> for container components. In React, JSX is first-class data (objects), which makes component composition much more flexible:

Pattern 1: The Default children Slot

Any JSX placed between opening and closing component tags is received as props.children (typed as React.ReactNode):

interface CardProps {
  title: string;
  children: React.ReactNode;
}

export function Card({ title, children }: CardProps) {
  return (
    <div className="card">
      <h3 className="card-title">{title}</h3>
      <div className="card-body">{children}</div>
    </div>
  );
}
Pattern 2: Multi-Slot Projection via Named Slot Props

In Angular, you use CSS selector multi-slot projection: <ng-content select="[card-header]">. In React, simply define separate props of type React.ReactNode:

interface ModalProps {
  header?: React.ReactNode;
  footer?: React.ReactNode;
  children: React.ReactNode;
  isOpen: boolean;
}

export function Modal({ header, footer, children, isOpen }: ModalProps) {
  if (!isOpen) return null;
  return (
    <div className="modal-backdrop">
      <div className="modal-dialog">
        {header && <div className="modal-header">{header}</div>}
        <div className="modal-body">{children}</div>
        {footer && <div className="modal-footer">{footer}</div>}
      </div>
    </div>
  );
}

// Consumer Usage:
<Modal
  isOpen={isOpen}
  header={<h2>Confirm Deletion</h2>}
  footer={<button onClick={handleDelete}>Delete</button>}
>
  <p>Are you sure you want to permanently delete this user?</p>
</Modal>
Pattern 3: Contextual Projection via Render Props (Template Outlets)

In Angular, when you need a reusable list or table component where the parent defines how each row looks, you use <ng-template let-user="user"> with *ngTemplateOutlet. In React, this is a Render Prop (a callback prop that accepts item data and returns JSX):

interface ListProps<T> {
  items: T[];
  renderItem: (item: T, index: number) => React.ReactNode;
  keyExtractor: (item: T) => string | number;
}

export function List<T>({ items, renderItem, keyExtractor }: ListProps<T>) {
  return (
    <ul className="list-container">
      {items.map((item, index) => (
        <li key={keyExtractor(item)} className="list-row">
          {renderItem(item, index)}
        </li>
      ))}
    </ul>
  );
}

// Consumer Usage:
<List
  items={users}
  keyExtractor={(u) => u.id}
  renderItem={(user) => (
    <div className="user-badge">
      <strong>{user.name}</strong> <span>({user.role})</span>
    </div>
  )}
/>

3. Side-by-Side Code Comparison: Enterprise Modal Component

Compare an enterprise modal dialog featuring multi-slot projection (header, footer, body), prop inputs, and dismissal event outputs in Angular vs. React:

Angular Component (TypeScript + HTML)

// modal.component.ts
import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-modal',
  templateUrl: './modal.component.html',
  styleUrls: ['./modal.component.css']
})
export class ModalComponent {
  @Input() isOpen = false;
  @Input() size: 'sm' | 'md' | 'lg' = 'md';
  @Output() closed = new EventEmitter<void>();

  close(): void {
    this.closed.emit();
  }
}

<!-- modal.component.html -->
<div *ngIf="isOpen" class="modal-overlay" (click)="close()">
  <div class="modal-box modal-{{ size }}" (click)="$event.stopPropagation()">
    
    <!-- Header Slot -->
    <div class="modal-header">
      <ng-content select="[slot-header]"></ng-content>
      <button class="close-btn" (click)="close()">&times;</button>
    </div>

    <!-- Default Body Slot -->
    <div class="modal-body">
      <ng-content></ng-content>
    </div>

    <!-- Footer Slot -->
    <div class="modal-footer">
      <ng-content select="[slot-footer]"></ng-content>
    </div>

  </div>
</div>

React Component (TSX + Functional Props)

// Modal.tsx
import React from 'react';
import clsx from 'clsx';

export interface ModalProps {
  isOpen: boolean;
  size?: 'sm' | 'md' | 'lg';
  onClose: () => void;
  header?: React.ReactNode;
  footer?: React.ReactNode;
  children: React.ReactNode;
}

export function Modal({
  isOpen,
  size = 'md',
  onClose,
  header,
  footer,
  children,
}: ModalProps) {
  if (!isOpen) return null;

  return (
    <div className="modal-overlay" onClick={onClose}>
      <div
        className={clsx('modal-box', `modal-${size}`)}
        onClick={(e) => e.stopPropagation()}
      >
        {/* Header Slot */}
        <div className="modal-header">
          <div className="header-title">{header}</div>
          <button className="close-btn" onClick={onClose}>
            &times;
          </button>
        </div>

        {/* Default Body Slot */}
        <div className="modal-body">{children}</div>

        {/* Footer Slot */}
        {footer && <div className="modal-footer">{footer}</div>}
      </div>
    </div>
  );
}

4. Critical Differences & Gotchas for Angular Leads

  1. Props are Strictly Immutable (Read-Only):
    In Angular, modifying an @Input() property (e.g. this.user.name = 'Alice') will physically mutate the parent object, causing unpredictable bugs. In React, mutating props is strictly forbidden. Any change to data must be signaled via callback to the parent component that owns the state.
  2. Avoid React.FC (FunctionComponent):
    Early React TypeScript tutorials used const Modal: React.FC<Props> = .... Modern React TypeScript best practice is standard function declaration with typed props: export function Modal({ isOpen }: ModalProps).
  3. React.ReactNode vs React.ReactElement:
    Always type children and slots as React.ReactNode. ReactNode includes everything React can render (JSX elements, strings, numbers, fragments, booleans, null, arrays). ReactElement only represents a single JSX object.
  4. Slot Fallbacks:
    In Angular, conditional fallback content inside <ng-content> is tricky. In React, it is standard JavaScript: {header ?? <h2>Default Header</h2>}.
  5. Solving Prop Drilling with Composition:
    In Angular, developers often create a service to avoid passing inputs through 3 levels of child components. In React, passing components as children or slot props lets parent components compose directly, bypassing intermediate components completely without needing global state!
