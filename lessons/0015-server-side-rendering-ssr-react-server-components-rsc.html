Lesson 0015: SSR & React Server Components (RSC)

Translating Angular Universal & SSR Hydration to Next.js App Router, React Server Components, 'use client', Server Actions, and Streaming Suspense

1. SSR & Server Components Translation Matrix

Angular provides Server-Side Rendering (SSR) via Angular Universal and modern client hydration (provideClientHydration()), where the entire component tree is rendered on Node.js and re-executed during client hydration. In React, Next.js App Router and React Server Components (RSC) introduce a hybrid architecture where server components execute only on the server (sending zero JavaScript to the client) while interactive client islands use the 'use client' directive.

Concept Angular (Web) React (Web)
SSR Prerendering Angular Universal / provideClientHydration() Next.js App Router (Automatic SSR on route requests)
Server-Only Components N/A (All Angular components are sent to the client bundle) React Server Components (Default): Run exclusively on the server with 0 KB client JavaScript bundle
Client Interactivity Boundary isPlatformBrowser(platformId) checks 'use client' directive at the top of interactive component files
Server Form Mutations Calling backend Express / Nest REST APIs Server Actions: 'use server' async functions invoked directly from forms and buttons
Direct Database & Secret Access Forbidden (Client components cannot access DB/secrets) Fully supported inside Server Components (query Postgres, Prisma, or read private ENV keys directly in JSX!)
Progressive Streaming Angular @defer blocks React <Suspense fallback={<Skeleton />}> streaming HTML chunks over HTTP
📦 Primary Full-Stack React Frameworks
  • next: The standard production framework implementing React Server Components, file-system routing, and Server Actions.
  • react (v19) & react-dom: Core libraries with native RSC and streaming support.

2. Architecture: Server Components vs. Client Components

In Next.js App Router, every component is a Server Component by default:

1. Server Components (No 'use client' directive):
  • Can fetch data directly from databases (e.g. Prisma, SQL, filesystem).
  • Can keep secret API tokens and backend credentials secure from browser inspection.
  • Send zero JavaScript to the client browser (reducing bundle size).
  • Cannot use hooks (useState, useEffect) or DOM event listeners (onClick).
2. Client Components ('use client' at top of file):
  • Can use state, effects, custom hooks, and event handlers (onClick, onChange).
  • Prerendered on the server as HTML, then hydrated in the browser with JavaScript.
  • Used as small "leaves" on the component tree for interactive elements.

3. Side-by-Side Code Comparison: Product Details Page with Secure DB Fetch & Interactive Cart Widget

Compare how a secure product page with database queries and an interactive "Add to Cart" button is built in Angular Universal vs. Next.js App Router (RSC):

Angular Universal (Client Component + Backend API)

// product.component.ts
import { Component, OnInit } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { ActivatedRoute } from '@angular/router';

@Component({
  selector: 'app-product',
  template: `
    <div *ngIf="product">
      <h1>{{ product.title }}</h1>
      <p>{{ product.price | currency }}</p>
      <button (click)="addToCart()">Add to Cart</button>
    </div>
  `
})
export class ProductComponent implements OnInit {
  product: any;
  constructor(private http: HttpClient, private route: ActivatedRoute) {}

  ngOnInit(): void {
    // Requires a separate backend REST API endpoint
    const id = this.route.snapshot.paramMap.get('id');
    this.http.get(`/api/products/${id}`).subscribe(data => this.product = data);
  }

  addToCart(): void {
    console.log('Added to cart');
  }
}

Next.js App Router (RSC + Client Island)

// app/products/[id]/page.tsx (Server Component)
import { db } from '@/lib/db'; // Direct database access!
import { AddToCartButton } from './AddToCartButton';
import { Suspense } from 'react';

export default async function ProductPage({ params }: { params: { id: string } }) {
  // Direct DB query on server — no client bundle, no separate API route!
  const product = await db.product.findUnique({ where: { id: params.id } });

  if (!product) return <div>Product not found</div>;

  return (
    <div className="product-card">
      <h1>{product.title}</h1>
      <p>${product.price.toFixed(2)}</p>
      {/* Interactive client island */}
      <AddToCartButton productId={product.id} />
    </div>
  );
}

// app/products/[id]/AddToCartButton.tsx ('use client')
'use client';
import React, { useState } from 'react';

export function AddToCartButton({ productId }: { productId: string }) {
  const [added, setAdded] = useState(false);

  return (
    <button onClick={() => setAdded(true)}>
      {added ? 'Added to Cart ✓' : 'Add to Cart'}
    </button>
  );
}

4. Critical SSR & RSC Gotchas for Angular Leads

  1. 'use client' Does NOT Mean "Execute Only in Browser":
    A common misconception is that 'use client' components only run in the browser. In reality, Client Components are still prerendered to HTML on the server during initial page load! Therefore, never access window or localStorage directly in the component body without guarding it inside a useEffect.
  2. Push 'use client' to the Leaves of Your Tree:
    If you place 'use client' at the top of a page or layout, that entire subtree becomes a Client Component, sacrificing the bundle size benefits of Server Components. Keep layouts and pages as Server Components and extract only interactive buttons/inputs into small client files.
