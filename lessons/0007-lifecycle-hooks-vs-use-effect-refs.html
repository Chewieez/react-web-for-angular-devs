Lesson 0007: Lifecycle Hooks vs. useEffect & Refs

Translating ngOnInit, ngOnDestroy, ngOnChanges, ngAfterViewInit, and @ViewChild to React useEffect synchronization, cleanup returns, and useRef

1. Lifecycle & DOM References Translation Matrix

In Angular, components follow a strict, time-based class lifecycle (constructor → ngOnChanges → ngOnInit → ngAfterViewInit → ngOnDestroy). In React, functional components have no time-based lifecycle methods: useEffect is a synchronization mechanism that connects React state to external systems, while useRef holds mutable values and direct DOM references without triggering re-renders.

(Empty dependency array runs once on mount)

(Returned function runs on unmount)

(Runs when propValue reference changes)

2. Deep Dive: Lifecycles vs. Synchronization with External Systems

The single biggest paradigm shift for Angular developers is understanding what useEffect is designed for:

The Angular Mental Model (Time Checkpoints):

In Angular, you think: "When this component initializes (ngOnInit), fetch data. When an input changes (ngOnChanges), recalculate state. When it destroys (ngOnDestroy), clean up."

The React Mental Model (Synchronize External Systems):

In React, an Effect does not represent a point in time; it represents synchronization with something outside of React's render loop (e.g. Browser Event Listeners, WebSockets, Timers, LocalStorage, or 3rd-party non-React libraries like Chart.js or Mapbox).

⚡ "You Might Not Need an Effect" (The Golden React Rule):

Angular developers often write unnecessary useEffect hooks to sync props into local state. If a value can be computed directly from existing props or state, compute it inline during render instead of triggering an extra effect and re-render cycle!

3. `useRef`: The Two Distinct Superpowers

In Angular, you use @ViewChild for DOM elements and class properties for instance variables. In React, the useRef hook handles both with two distinct use cases:

Superpower 1: Referencing Native DOM Nodes (Focus, Scroll, Measurements) 
import { useRef } from 'react';

export function SearchInput() {
  const inputRef = useRef<HTMLInputElement>(null);

  function handleFocus() {
    inputRef.current?.focus();
  }

  return (
    <>
      <input ref={inputRef} placeholder="Search..." />
      <button onClick={handleFocus}>Focus Input</button>
    </>
  );
}
Superpower 2: Storing Mutable Values Across Renders (Without Triggering Re-Renders)

Updating useState schedules a re-render. Updating ref.current = value does not re-render. This makes refs ideal for timer IDs, AbortControllers, WebSocket connection handles, and tracking previous state:

export function AutoTimer() {
  const [seconds, setSeconds] = useState(0);
  const timerIdRef = useRef<number | null>(null);

  function start() {
    if (timerIdRef.current !== null) return;
    timerIdRef.current = window.setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);
  }

  function stop() {
    if (timerIdRef.current !== null) {
      clearInterval(timerIdRef.current);
      timerIdRef.current = null;
    }
  }

  return <div>Seconds: {seconds} <button onClick={start}>Start</button> <button onClick={stop}>Stop</button></div>;
}

4. Side-by-Side Code Comparison: Real-Time WebSocket Terminal with Auto-Scroll

Compare how a live WebSocket log stream with auto-scrolling DOM container, window resize listening, and comprehensive teardown cleanup is built in Angular vs. React:

Angular Component (Lifecycle Methods + ViewChild)

// log-terminal.component.ts
import { Component, OnInit, OnDestroy, ViewChild, ElementRef, AfterViewChecked } from '@angular/core';

@Component({
  selector: 'app-terminal',
  templateUrl: './log-terminal.component.html'
})
export class LogTerminalComponent implements OnInit, OnDestroy, AfterViewChecked {
  @ViewChild('scrollContainer') private scrollContainer!: ElementRef;
  logs: string[] = [];
  private socket!: WebSocket;
  private resizeHandler = () => this.handleResize();

  ngOnInit(): void {
    // 1. Connect external WebSocket
    this.socket = new WebSocket('wss://api.example.com/logs');
    this.socket.onmessage = (event) => {
      this.logs.push(event.data);
    };

    // 2. Add browser window event listener
    window.addEventListener('resize', this.resizeHandler);
  }

  ngAfterViewChecked(): void {
    // 3. Scroll to bottom
    this.scrollToBottom();
  }

  ngOnDestroy(): void {
    // 4. Teardown WebSocket & event listener
    this.socket.close();
    window.removeEventListener('resize', this.resizeHandler);
  }

  private scrollToBottom(): void {
    if (this.scrollContainer) {
      const el = this.scrollContainer.nativeElement;
      el.scrollTop = el.scrollHeight;
    }
  }

  private handleResize(): void {
    console.log('Window resized');
  }
}

React Component (useEffect Synchronization + useRef)

// LogTerminal.tsx
import React, { useState, useEffect, useRef } from 'react';

export function LogTerminal() {
  const [logs, setLogs] = useState<string[]>([]);
  const terminalRef = useRef<HTMLDivElement>(null);

  // Effect 1: Synchronize with WebSocket external data stream
  useEffect(() => {
    const socket = new WebSocket('wss://api.example.com/logs');
    
    socket.onmessage = (event) => {
      setLogs((prevLogs) => [...prevLogs, event.data]);
    };

    // Automatic cleanup on unmount
    return () => {
      socket.close();
    };
  }, []); // Empty deps = connect on mount, close on unmount

  // Effect 2: Synchronize with window resize events
  useEffect(() => {
    function handleResize() {
      console.log('Window resized');
    }

    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  // Effect 3: Auto-scroll whenever new logs arrive
  useEffect(() => {
    if (terminalRef.current) {
      terminalRef.current.scrollTop = terminalRef.current.scrollHeight;
    }
  }, [logs]);

  return (
    <div className="terminal-wrapper">
      <div ref={terminalRef} className="terminal-logs" style={{ maxHeight: 300, overflowY: 'auto' }}>
        {logs.map((log, index) => (
          <div key={index} className="log-entry">{log}</div>
        ))}
      </div>
    </div>
  );
}

5. Critical Gotchas for Angular Leads

  1. React 18/19 Strict Mode Double-Mounting:
    In development mode with <React.StrictMode>, React deliberately mounts, unmounts, and re-mounts every component (setup → cleanup → setup). This intentionally exposes bugs where developers forget to remove event listeners, abort fetches, or close WebSockets in their cleanup function!
  2. The Infinite Re-Render Loop:
    Calling setState inside useEffect without passing a dependency array (useEffect(() => { setCount(c => c + 1); })) causes an infinite render loop: render → effect runs → state changes → re-render → effect runs again.
  3. Do NOT Read or Write ref.current During Render:
    Never modify or read ref.current inside the body of your component function during JSX generation (e.g. ref.current = count + 1). Only access refs inside useEffect callbacks or event handlers to ensure pure, predictable rendering.
  4. useLayoutEffect vs. useEffect:
    useEffect runs asynchronously after the browser paints the screen (preventing UI blocking). Use useLayoutEffect only when you need to synchronously measure DOM nodes before the user sees the screen to prevent visual layout flicker (e.g. tooltip popover positioning).
