Lesson 0006: State Management Fundamentals

Translating Angular Signals, computed(), effect(), and BehaviorSubjects to React useState, Derived State, useMemo, and useReducer

1. Reactive State Translation Matrix

Angular and React handle reactivity with fundamentally different mental models. Angular uses a push/pull reactive dependency graph (Signals) or stream subscriptions (RxJS), where updates target specific DOM bindings. React uses a functional re-execution model, where updating state re-invokes the component function from top to bottom and reconciles the resulting Virtual DOM tree.

Concept Angular (Web) React (Web)
Writable Local State count = signal(0);
this.count.set(5);		 const [count, setCount] = useState(0);
setCount(5);
Functional State Updates this.count.update(n => n + 1); setCount(prev => prev + 1);
(Updater function ensures latest state)
Computed / Derived State double = computed(() => this.count() * 2); const double = count * 2; (Inline)
or useMemo(() => count * 2, [count])
Complex Multi-Field Transitions BehaviorSubject<State> / Service methods const [state, dispatch] = useReducer(reducer, initial);
Side Effects on State Change effect(() => { console.log(this.count()); }); useEffect(() => { console.log(count); }, [count]);
Lazy State Initialization Class property constructor / factory useState(() => computeExpensiveInitialValue())
State Immutability Rule Signals allow object references (though immutability is recommended) Strictly Immutable: Must return new object/array references via spread ({...obj}, .map(), .filter())

2. Reactivity Deep Dive: Dependency Graphs vs. Function Re-executions

Understanding the runtime difference between Angular Signals and React Hooks is essential to writing performant React code and avoiding common bugs:

Angular Signals: Granular Dependency Graph

In Angular, calling count.set(5) notifies only the consumers (template nodes, computed signals, or effects) that directly read count(). The component class instance is created once and stays in memory; the component method or template is not re-executed in its entirety.

React Hooks: Component Function Re-Execution

In React, calling setCount(5) schedules a re-render. React re-runs the entire component function from line 1 to the return statement. Local variables are re-evaluated, and JSX is regenerated. React preserves state values between these function executions by tracking hook call order inside its internal Fiber data structure.

3. Derived State: Plain Variables vs. `useMemo`

One of the most common anti-patterns for Angular engineers coming to React is creating duplicate useState hooks for values that can simply be calculated during render.

Anti-Pattern (Redundant State & Out-of-Sync Bugs): 
// ❌ BAD: Storing derived values in separate state
const [firstName, setFirstName] = useState('Ada');
const [lastName, setLastName] = useState('Lovelace');
const [fullName, setFullName] = useState(''); // Redundant!

// Forcing a sync effect leads to unnecessary re-renders and glitch states:
useEffect(() => {
  setFullName(`${firstName} ${lastName}`);
}, [firstName, lastName]);
The React Way (Calculate During Render): 
// ✅ GOOD: Plain JavaScript variable calculated on every render
const [firstName, setFirstName] = useState('Ada');
const [lastName, setLastName] = useState('Lovelace');

// Computed instantly in microseconds during function execution:
const fullName = `${firstName} ${lastName}`;

When should you use useMemo? Only when the calculation is computationally expensive (e.g. filtering/sorting an array of thousands of items) or when you need referential stability for dependency arrays:

// ✅ Use useMemo ONLY for expensive filtering/sorting or reference caching:
const visibleUsers = useMemo(() => {
  return users.filter(u => u.role === selectedRole).sort((a, b) => a.score - b.score);
}, [users, selectedRole]);

4. Side-by-Side Code Comparison: Interactive Inventory & Order Widget

Compare how an interactive product inventory manager with category filtering, search, quantity updates, and dynamic price totals is built in Angular (Signals) vs. React (useState & derived calculations):

Angular Component (Signals & Computed)

// inventory.component.ts
import { Component, signal, computed } from '@angular/core';

interface Item {
  id: string;
  name: string;
  price: number;
  quantity: number;
  category: 'electronics' | 'books';
}

@Component({
  selector: 'app-inventory',
  templateUrl: './inventory.component.html'
})
export class InventoryComponent {
  // Writable Signals
  items = signal<Item[]>([
    { id: '1', name: 'Mechanical Keyboard', price: 120, quantity: 1, category: 'electronics' },
    { id: '2', name: 'TypeScript Handbook', price: 40, quantity: 2, category: 'books' }
  ]);
  selectedCategory = signal<string>('all');

  // Computed Signals
  filteredItems = computed(() => {
    const cat = this.selectedCategory();
    const list = this.items();
    return cat === 'all' ? list : list.filter(i => i.category === cat);
  });

  totalPrice = computed(() => {
    return this.filteredItems().reduce(
      (sum, item) => sum + item.price * item.quantity, 0
    );
  });

  updateQuantity(id: string, delta: number): void {
    this.items.update(currentItems =>
      currentItems.map(item =>
        item.id === id
          ? { ...item, quantity: Math.max(0, item.quantity + delta) }
          : item
      )
    );
  }
}

React Component (useState & Derived State)

// Inventory.tsx
import React, { useState, useMemo } from 'react';

interface Item {
  id: string;
  name: string;
  price: number;
  quantity: number;
  category: 'electronics' | 'books';
}

const INITIAL_ITEMS: Item[] = [
  { id: '1', name: 'Mechanical Keyboard', price: 120, quantity: 1, category: 'electronics' },
  { id: '2', name: 'TypeScript Handbook', price: 40, quantity: 2, category: 'books' }
];

export function Inventory() {
  const [items, setItems] = useState<Item[]>(INITIAL_ITEMS);
  const [selectedCategory, setSelectedCategory] = useState<string>('all');

  // Derived calculation during render (no useEffect needed!)
  const filteredItems = useMemo(() => {
    return selectedCategory === 'all'
      ? items
      : items.filter(i => i.category === selectedCategory);
  }, [items, selectedCategory]);

  // Derived instant total
  const totalPrice = filteredItems.reduce(
    (sum, item) => sum + item.price * item.quantity, 0
  );

  // Updater function prevents race conditions
  function handleUpdateQuantity(id: string, delta: number) {
    setItems(prevItems =>
      prevItems.map(item =>
        item.id === id
          ? { ...item, quantity: Math.max(0, item.quantity + delta) }
          : item
      )
    );
  }

  return (
    <div className="inventory-card">
      <div className="controls">
        <label>Category:</label>
        <select
          value={selectedCategory}
          onChange={(e) => setSelectedCategory(e.target.value)}
        >
          <option value="all">All Categories</option>
          <option value="electronics">Electronics</option>
          <option value="books">Books</option>
        </select>
      </div>

      <ul className="item-list">
        {filteredItems.map(item => (
          <li key={item.id} className="item-row">
            <span>{item.name} (${item.price})</span>
            <div className="qty-controls">
              <button onClick={() => handleUpdateQuantity(item.id, -1)}>-</button>
              <span>Qty: {item.quantity}</span>
              <button onClick={() => handleUpdateQuantity(item.id, 1)}>+</button>
            </div>
          </li>
        ))}
      </ul>

      <div className="summary">
        <strong>Total Price: ${totalPrice.toFixed(2)}</strong>
      </div>
    </div>
  );
}

5. Critical State Gotchas for Angular Leads

  1. Mutating Objects/Arrays Directly (The Reference Equality Trap):
    React uses Object.is(oldState, newState) to decide if a re-render is necessary. If you write: 
    // ❌ WILL NOT RE-RENDER:
items.push(newItem);
setItems(items); // Same array memory address!
    Always create a new array or object copy: 
    // ✅ CORRECT:
setItems([...items, newItem]);
  2. Updater Functions vs. Direct Values in Event Handlers:
    State updates inside React 18/19 are automatically batched. If you call: 
    setCount(count + 1);
setCount(count + 1);
    Both calls read the same closure snapshot of count (e.g. 0 + 1). The result will be 1, not 2.
    Fix: Use the updater function syntax: setCount(prev => prev + 1).
  3. Lazy State Initialization:
    If your initial state requires reading localStorage or running a heavy parse, do not call it directly inside useState(readStorage()) (which runs on every single render). Pass a function instead: 
    // ✅ Evaluated ONLY once on initial mount:
const [token, setToken] = useState(() => localStorage.getItem('auth_token'));
