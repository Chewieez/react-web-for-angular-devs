Lesson 0006: Angular Services & DI vs. React Context & Custom Hooks

Translating @Injectable singletons, hierarchical injectors, and inject() tokens to createContext, React 19 Context Providers, and composable custom hooks

1. Dependency Injection & Services Translation Matrix

Angular features a robust, hierarchical Dependency Injection (DI) container built directly into the framework. React does not have a global DI container or class-based service injector; instead, React separates logic sharing into Composable Custom Hooks (for reusable stateful logic) and React Context (for passing data down a component subtree without prop drilling).

2. Architecture: Service Classes vs. Composable Custom Hooks

Angular developers are accustomed to placing shared logic into @Injectable() classes. In React, you must understand the distinction between sharing stateful logic vs. sharing state instances:

1. Custom Hooks Share Logic, NOT State Instances:

A Custom Hook is simply a JavaScript function whose name starts with use that can call other React hooks. Every component that calls a custom hook gets its own isolated state.

// useCounter.ts — Reusable counter logic
export function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);
  const increment = () => setCount(c => c + 1);
  const decrement = () => setCount(c => c - 1);
  return { count, increment, decrement };
}

// ComponentA and ComponentB will EACH have their own independent count:
function ComponentA() { const { count, increment } = useCounter(); ... }
function ComponentB() { const { count, increment } = useCounter(); ... }
2. React Context Shares a Single State Instance Down a Tree:

When you want multiple components in a tree to read and update the exact same state instance (e.g. Current User, Color Theme, Active Workspace), you combine React Context with a Custom Hook:

// The Gold Standard Pattern: Context + Provider Component + Custom Hook Guard
const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const value = useMemo(() => ({ user, setUser }), [user]);

  // In React 19: 
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuth(): AuthContextValue {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within an <AuthProvider>');
  }
  return context;
}

3. Modern React 19 Context Enhancements

React 19 streamlines Context usage with two key improvements:

1. Direct Context Provider Element:

You no longer need <ThemeContext.Provider value={...}>. You can now render <ThemeContext value={...}> directly:

// React 19 Syntax:
return (
  <ThemeContext value="dark">
    <App />
  </ThemeContext>
);
2. The use() Hook for Conditional Context:

Unlike useContext(), which cannot be called inside loops or conditional blocks, React 19 introduces the use() API which can be called conditionally:

import { use } from 'react';

function UserProfile({ isPremium }: { isPremium: boolean }) {
  // ✅ Valid in React 19: conditionally reading context
  if (isPremium) {
    const premiumConfig = use(PremiumConfigContext);
    return <PremiumBadge config={premiumConfig} />;
  }
  return <StandardBadge />;
}

4. Side-by-Side Code Comparison: Enterprise Authentication & Session Management

Compare how a production session authentication service is structured in Angular (Injectable class with RxJS BehaviorSubject) vs. React (Context + Provider + Custom Hook):

Angular Authentication Service (DI Class)

// auth.service.ts
import { Injectable } from '@angular/core';
import { BehaviorSubject, map } from 'rxjs';

export interface User {
  id: string;
  name: string;
  role: 'admin' | 'user';
}

@Injectable({
  providedIn: 'root'
})
export class AuthService {
  private userSubject = new BehaviorSubject<User | null>(null);
  user$ = this.userSubject.asObservable();
  isAuthenticated$ = this.user$.pipe(map(user => !!user));

  login(user: User): void {
    this.userSubject.next(user);
  }

  logout(): void {
    this.userSubject.next(null);
  }

  get currentUser(): User | null {
    return this.userSubject.getValue();
  }
}

// Consumer Component:
@Component({ ... })
export class NavComponent {
  constructor(public auth: AuthService) {}
}

React Context & Custom Hook (TSX)

// AuthContext.tsx
import React, { createContext, useContext, useState, useMemo, useCallback } from 'react';

export interface User {
  id: string;
  name: string;
  role: 'admin' | 'user';
}

interface AuthContextType {
  user: User | null;
  isAuthenticated: boolean;
  login: (user: User) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextType | null>(null);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);

  const login = useCallback((userData: User) => setUser(userData), []);
  const logout = useCallback(() => setUser(null), []);

  const value = useMemo(() => ({
    user,
    isAuthenticated: Boolean(user),
    login,
    logout
  }), [user, login, logout]);

  return <AuthContext value={value}>{children}</AuthContext>;
}

// Consumer Hook:
export function useAuth(): AuthContextType {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used inside <AuthProvider>');
  return ctx;
}

// Consumer Component:
export function Nav() {
  const { user, isAuthenticated, logout } = useAuth();
  return <nav>...</nav>;
}

5. Critical DI & Context Gotchas for Angular Leads

  1. Context is NOT a High-Frequency State Manager:
    In Angular, services using Signals or RxJS allow components to subscribe to specific values without re-rendering everything. In React, whenever any value in a Context updates, every single component consuming that Context re-renders. Use Context for low-frequency updates (Auth, Theme, Locale). For high-frequency state (e.g. cart updates, interactive forms, 60fps animations), use zustand.
  2. Always Memoize the Context Value Object:
    If you write <AuthContext value={{ user, login }}> without useMemo, a new object literal is created on every render of the Provider. This forces all consumer components to re-render even if user has not changed!
  3. Custom Hooks Don't Create Singletons:
    In Angular, injecting a service into two components gives both components the same class instance. In React, calling a custom hook creates a completely separate state instance in each component unless wrapped by a Context Provider.
  4. Always Add a Fail-Fast Guard in Custom Hooks:
    Always check if (!context) throw new Error('...') in your custom hook. This catches missing Provider errors immediately during development with a crystal-clear error message.
